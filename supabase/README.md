# BISA Supabase and Vercel setup

BISA keeps its existing HTML, CSS and browser JavaScript. The `api/` directory contains Vercel Node.js functions; application data and media are not stored in browser localStorage.

## 1. Prepare Supabase

1. Use the Supabase project intended for BISA and take a backup before changing an existing database.
2. For a new project, run [`schema.sql`](./schema.sql) in the Supabase SQL Editor.
3. For an existing project created with the earlier BISA demo schema, inspect the database first and then run [`migrations/202611110001_secure_marketplace.sql`](./migrations/202611110001_secure_marketplace.sql). It adds the server-backed workflow and removes the demo's overly broad table policies. Review the SQL against project-specific policies before applying it.
4. The SQL creates the private `business-media` Storage bucket. It accepts JPG, PNG, WEBP, GIF, MP4, WEBM and MOV, with a 25MB bucket limit. The application form additionally enforces 5MB per image.
5. In Supabase Authentication, disable public sign-up. Set the production site URL and redirect URLs for administrator invitations, and configure email delivery so invitations and password resets reach the intended administrators.

The browser only uses the Supabase anon key for administrator sign-in. Vercel functions use the service-role key and verify administrator roles before every protected operation. Application and applicant data have no public read or write policy; public visitors see published business records only. Private media is accessed through short-lived signed URLs generated by the server.

The database trigger creates a matching profile for new Supabase Auth users. The SQL inserts nothing if the invitation has not yet been accepted and its profile has not been created. Do not add a public registration page or grant administrator roles from browser code. The primary administrator can invite team members from the private BISA dashboard.

Roles:

- `super_admin`: full access, including team invitations and role management.
- `application_manager`: reviews applications and sends applicant SMS updates.
- `content_manager`: edits business listings, products/services and homepage text.
- `moderator`: reviews and updates application status.

## 3. Configure Vercel

In the existing BISA Vercel project's Settings → Environment Variables, set these values for the environments you use:

| Variable | Purpose | Exposure |
|---|---|---|
| `SUPABASE_URL` | Supabase project URL | Returned by the public config endpoint |
| `SUPABASE_ANON_KEY` | Supabase anon/publishable key for Auth | Returned by the public config endpoint |
| `SUPABASE_SERVICE_ROLE_KEY` | Server-side database and private storage access | Server only; never expose or commit |
| `ARKESEL_API_KEY` | Arkesel SMS API key | Server only; never expose or commit |
| `ARKESEL_SENDER_ID` | Registered SMS sender name | Server only |

Redeploy after setting environment variables. `SUPABASE_SERVICE_ROLE_KEY` bypasses Row Level Security and must only be available to the Vercel functions. Do not put it in `script.js`, a public config file, or browser-visible variables. Keep real secrets out of `.env.example` and source control.

The SMS endpoint uses Arkesel's documented Ghana-capable SMS API. Register and activate the sender ID in Arkesel before enabling SMS. A provider response is recorded as sent only when Arkesel returns its documented success code; failures are recorded and shown as failures.

## 4. Local development

For static layout-only preview, run `python -m http.server 8000`. Backend operations require the Vercel functions and configured Supabase environment. Use the Vercel CLI's local development server (`vercel dev`) with local environment variables to test applications, authentication, media uploads, admin workflows and SMS. Do not use real SMS credits for a test unless you intend to send a message.

The public application upload flow requests short-lived signed upload URLs, uploads files directly to private Supabase Storage, and sends the verified media paths and application details to the server. The server verifies file type signatures and size, saves the application as `PENDING`, generates its reference, and records the activity. Approval creates an unpublished draft; an administrator must explicitly publish the business.

## 5. What is not configured automatically

This repository does not contain the existing Supabase project's URL, anon key, or service-role key. Configure them in the existing BISA Vercel project's Environment Variables; do not put the service-role key in source control or chat. Arkesel credentials are optional until SMS is enabled. The official BISA logo assets are stored in `assets/`.
